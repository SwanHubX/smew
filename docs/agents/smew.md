# smew（平滑算法库）

**适用范围**：整个仓库 **读完能回答**：改算法要动哪几层、一致性怎么判定、产物怎么同步

## 必须遵守

### 1. 接口以代码为准

接口签名与语义不在此复述，以代码与声明文件为准：

- 公共入口：`index.ts`
- 类型声明：`types/index.d.ts`（与构建产物中的声明保持一致）
- 一致性判定：`tests/parity.test.ts`

三个导出函数的签名与语义已冻结，任何变更必须先评审，并同步更新声明文件。

### 2. 分层

| 层          | 职责                                                |
| ----------- | --------------------------------------------------- |
| 算法层      | 纯 Rust，输入输出为 `&[f64] → Vec<f64>`，不接触绑定 |
| 数值内核    | 共享的数值原语，与 TS 正本同名函数逐字镜像          |
| 绑定层      | wasm-bindgen 导出，负责 JS 类型转换                 |
| JS 公共入口 | 按类型分派、默认导出与单算法命名导出                |

绑定只允许出现在绑定层；算法层必须能在原生工具链下直接测试。

### 3. 一致性判定

- **行为权威源是 TS 实现**：两侧不一致时默认 TS 为准；有意的行为变更属于接口变更，必须声明并评审。
- 算法改动必须包含或运行 JS↔Rust 对拍，同一组 fixture 下断言一致，不能用"肉眼对比曲线"替代。
- **位级一致**：输出与输入位置一一对应；缺失值只要求两侧同为缺失；有限值要求浮点位模式完全一致，不接受误差容差。
- **不要求位级一致的算法**：依赖超越函数的实现无法保证末位相同，判定标准为缺失位置与语义严格一致、有限值使用明确的绝对/相对误差容差；容差数值实测后冻结。
- 不得改变既定的浮点运算顺序（折叠次序、权重累加次序）；优化导致结果差异时，以未优化结果为准，或显式放宽标准并评审。

### 4. 缺失值语义

- 输出与输入等长、顺序对应；空数组返回空数组。
- 缺失值统一用 NaN 表达，JS 侧与 Rust 侧使用同一套有限性判定，不引入第二套口径。
- 各算法的状态推进、窗口重复使用、权重重新归一化规则必须与 TS 版逐条对齐。
- 参数非法值（NaN、负数、超出滑块范围）的处理方式必须与 TS 版一致，绑定层不信任调用方一定传合法值。

### 5. 产物同步

- 预构建产物位于 `dist/`，分两类：`index.js`（tsup 从 `index.ts` 编译的入口）与 `wasm.js` / `wasm.d.ts`（内嵌 wasm 字节的胶水，由 `scripts/inline-wasm.mjs` 生成）。公共 API 的声明文件在 `types/`，由 CI 做漂移守卫。
- 修改 `.rs`（重建 `wasm.js`）或 `index.ts` / `tsup.config.ts`（重建 `index.js`）的提交，必须在**同一提交**内重新生成并提交对应产物；生成后工作区仍有差异说明未同步。
- 不提交裸 `.wasm`、构建中间目录等中间产物。
- 声明文件必须与实际导出一致，不能只检查文件存在。
- 产物不依赖运行时按路径请求独立 wasm 文件；动态导入应进入异步 chunk，不进入首屏包。

### 6. 工程与横切

- crate 名、edition、crate-type 变更需说明理由。
- 新增依赖需评审，锁文件随依赖变更一起提交。
- **禁止 `unsafe`**；**禁止 panic 逃逸到 JS**（`unwrap` / `expect` / 越界索引 / 算术溢出）。
- 错误以缺失值输出或显式返回值表达，不用 panic 传播。
- 热路径不做重复分配：允许结果数组与算法必要辅助结构的分配，禁止每个输出点创建临时数组或重复克隆。
- 取消与时间分片由 JS 在数组之间处理，Rust 不感知调度。

### 7. 回退

- 公共入口内部调度：WASM 就绪时优先，未就绪或加载失败自动回退 TS 实现。
- 回退只告警一次，后续调用直接走 TS，不重复重试。
- TS 回退实现的行为保持与历史一致。
- 不提供引擎切换的环境变量开关；如需要，先更新契约再实现。

## 验证命令

Rust 侧在仓库根目录运行：

```bash
cargo fmt --check
cargo check
cargo test
cargo clippy --target wasm32-unknown-unknown
cargo build --target wasm32-unknown-unknown
```

TS 侧在仓库根目录运行：

```bash
npm run lint
npx tsc --build tsconfig.json
npm run test
```

产物同步不在 CI 中验证，由人工契约保证；可重建后检查产物目录有无差异。

## 常见错误

| 错误                             | 正解                 |
| -------------------------------- | -------------------- |
| 用误差容差判定要求位级一致的算法 | 位模式比较           |
| 改了运算顺序仍声称结果一致       | 保持折叠与累加顺序   |
| 绑定代码写进纯算法模块           | 绑定只在绑定层       |
| 改 `.rs` 不同步产物              | 同提交重建并提交     |
| 用 `unwrap` 处理可能失败的值     | 显式返回缺失值或错误 |

## 判断边界

- 只有"肉眼看着差不多"的验证不算通过。
- 纯文档或注释变更不触发产物同步要求。
- 子项目接口冻结，新增导出等同接口变更。
