# 提交信息

**适用范围**：所有 commit **读完能回答**：提交信息用什么语言、怎么写、怎么拆分

## 必须遵守

### 1. 语言

- 标题与正文全部用英文，不混入中文。
- 路径、命令、issue/PR 编号按原样引用，不翻译。

### 2. 标题

- 格式：`<type>: <english subject>`。
- `type` 取 `feat` / `fix` / `refactor` / `perf` / `test` / `docs` / `ci` / `chore`。
- 动词开头、小写、不加句号。

### 3. 意图单一

- 一次提交只表达一个意图。
- 功能、重构、格式化分开提交；混在一起无法单独回滚和 review。

### 4. 正文

- 提交信息是纯文本：提交时、以及在对话中给出时，都不要用 Markdown 代码块（` ``` `）、缩进或引用块包裹。
- 说明"为什么"，不复述 diff。
- 不写过程性内容，例如"上次改错本次修正"或 AI 工作记录。
- 破坏性变更、兼容影响、迁移方式必须写明。

### 5. 提交前

- 运行 lint、类型检查与相关测试，命令见 [smew.md](./smew.md) 的「验证命令」。
- 清理本次变更产生的死代码、临时打印与调试输出。

## 常见错误

| 错误                             | 正解                       |
| -------------------------------- | -------------------------- |
| 标题或正文用中文                 | 改成英文                   |
| `update code` / `fix bug`        | 写明改动对象与结果         |
| 一次提交混入格式化、重构与新功能 | 拆分提交                   |
| 正文复述 diff                    | 只写原因、取舍与影响       |
| 用 ` ``` ` 包裹提交信息          | 直接输出纯文本             |
| 留下过程性说明                   | 删除，只保留结论性内容     |
| 提交前没跑 lint / 类型检查       | 按「验证命令」补跑         |

## 判断边界

- 提交信息只约束格式、语言与意图，不要求措辞唯一。
- 仓库历史中的存量写法不作为新提交的依据。
- 分支名、PR 标题与描述不属于提交信息，见 [pr.md](./pr.md)。
